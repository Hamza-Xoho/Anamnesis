# The evaluation set — what to write and why

You are testing one thing: **can the grader tell understanding apart from fluent recall?**

Everything Anamnesis does downstream — the memory model, the confidence map, the scheduling — assumes it can. Phase 0 checks that assumption before you spend months on it. If it fails, the charter's fallback is to restrict v1 to domains with checkable answers, and that is a decision worth reaching in week two rather than month five.

## The rule about who writes these

**You write them. Not a model.**

This isn't bureaucracy. Learner errors have a shape: a real misconception, held confidently, that survived because nobody ever probed it. A model asked for "a confidently wrong answer" produces something subtly different and usually easier to spot — so the grader scores well on material that isn't the material it will actually face.

Legitimate sources, roughly best first:

| Source | `source:` value | Note |
|---|---|---|
| Your own past written answers, tutorial work, SAQ practice | `own-answer` | Best. Real artefacts of real attempts |
| Old exam scripts, marked or unmarked | `past-script` | Best. Especially the ones you got wrong |
| Classmates' answers, with permission | `peer-answer` | Very good — errors you would not have invented |
| Written now, from memory of a misconception you actually held | `own-recollection` | Fine, and unavoidable for some. Use sparingly for the *correct* halves |

Never: text generated by any model, including as a "placeholder to replace later."

## The three files

| File | Tests | What it proves |
|---|---|---|
| `matched-pairs.yaml` | SC-1, ≥90% | The grader is not fooled by fluency |
| `route-failures.yaml` | SC-4, ≥80% | The grader checks reasoning, not just conclusions |
| `kappa-sample.yaml` | Cohen's κ, substantial band | The grader agrees with a human beyond chance |

## Do a pilot first

Do **not** write 135 answers before finding out whether the grader is in the right postcode.

**Pilot: 10 matched pairs, 8 route-failure items, no κ sample.** Run the harness. Then:

- Near or above threshold → build the full set. You are measuring something real.
- Around 50–70% → the grader is close, but the prompt or your rubrics need work. Iterate *on the pilot*, cheaply, before scaling.
- Near chance → stop. That is the architecture decision this gate exists to force, and you reached it for a day of writing instead of a week.

**Full set, if the pilot justifies it:** 40 matched pairs across ~20 concepts, 25 route-failure items, 30 κ answers. Below about 25 pairs you cannot statistically distinguish 90% from 70%, so the gate stops being informative — that is the floor, not the target.

## The one result to be suspicious of

**If SC-1 comes back near 100%, something is wrong with your set, not right with your grader.**

It means every pair is obvious: the wrong answers cartoonishly wrong, the hedged ones transparently correct. You have measured the easy middle and skipped the boundary, which is the only part that matters. Deliberately include pairs *you* had to think about.

## Labelling

Each answer gets:

- **`verdict`** — `miss` · `partial` · `hit` · `effortless_hit`. Did they know it? Judge the content, not the prose.
- **`route_quality`** — `clean` · `route_failure` · `unassessable`. Did they get there the right way? A right conclusion via a wrong mechanism is `hit` + `route_failure`. That combination is the entire point of the second file.
- **`note`** — one line, for you. Why you labelled it that way. This is what you will re-read in six weeks when the grader disagrees and you cannot remember your reasoning.

Do **not** record how confident the answer *sounds*. Expressed confidence is the grader's third output and must never touch the verdict; labelling it yourself would leak the thing you are testing for.

## Freezing

Once the pilot is done and the full set written, commit it. From that point any change invalidates the gate, because a set you can edit after seeing the results is not a measurement. If you must change it, re-run the whole gate and say so.

`kappa-sample.yaml` carries a further rule: **do not open it while tuning the examiner prompt.** Its value is entirely in having been unseen.
